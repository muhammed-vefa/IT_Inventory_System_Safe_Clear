# CSS Technical Debt Report - Phase 4 Stabilization

## Analysis of `!important` Usage
Current Count: ~115 occurrences.

### Major Patterns Identified:
1. **Utility Overrides (30%):**
   - Classes like `.admin-only { display: none !important; }` and `.fab { display: none !important; }`.
   - Rationale: These are used to force state visibility regardless of specific card or component styles.
   - Status: **Safe to keep** as they act as global state modifiers.

2. **Browser/Select Overrides (20%):**
   - `select option { background-color: #1a1b26 !important; }`.
   - Rationale: Browsers (especially Chrome/Edge) are extremely stubborn with styling native `<option>` tags.
   - Status: **Necessary** until replaced by custom dropdown components.

3. **Interaction/Hover Inhibitors (25%):**
   - `transform: none !important;` or `cursor: default !important;` on specific cards to disable general hover effects.
   - Rationale: Used to differentiate between "view-only" cards and "interactive" cards within the same grid system.
   - Status: **Cleanup target**. Should be replaced by adding a `.non-interactive` class to the parent.

4. **Responsive Media Query Fixes (25%):**
   - `width: 100% !important;` inside `@media (max-width: 768px)`.
   - Rationale: Used to override fixed widths defined in the desktop view without increasing specificity.
   - Status: **Cleanup target**. Can be solved by using a mobile-first approach or better specificity in media queries.

## Recommended Actions:
- [ ] Implement `.no-hover` utility to replace transform/cursor `!important` hacks.
- [ ] Review `select` styling and evaluate `Choices.js` or similar for premium UX.
- [ ] Consolidate mobile overrides into a dedicated responsive section of `style.css` with proper specificity.
